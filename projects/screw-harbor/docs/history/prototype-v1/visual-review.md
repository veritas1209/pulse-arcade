# SCREW HARBOR — 독립 시각 리뷰

리뷰 범위: 현재 캡처 묶음과 제공된 성능 지표를 기준으로 한 독립 평가. 이전 점수나 구현 설명을 평가 근거로 쓰지 않았다. 점수는 0~3 기준이며, 장르에 맞춰 hero/player는 해체 대상 구조물, obstacles는 구조물의 가림층, world는 물리 작업대와 그 배경으로 읽었다. 인터랙션의 즉각 보상은 색 나사 이동과 부품 노출이다.

## 캡처 확인 범위

- 전체 갤러리 `artifacts/structure-collection.webp`와 stage 0–11의 진행 중 장면 `artifacts/active-0.png`–`active-11.png`를 모두 확인했다. 각 진행 장면은 서로 다른 구조물과 일부 나사 제거 상태를 보여 준다.
- `artifacts/desktop.png`, `artifacts/mobile.png`, `artifacts/liner.png`, `tests/visual.spec.ts-snapshots/workshop-desktop-chrome-win32.png`, `workshop-mobile-chrome-win32.png`, `pause-desktop-chrome-win32.png`, `pause-mobile-chrome-win32.png`를 확인했다.
- **실제 패배·복구 화면 캡처는 찾지 못했다.** `qa-rules-report.md`는 12번째 스테이지에서 버퍼가 차면 한국어 패배 모달이 열리고 undo가 플레이 상태·직전 나사·버퍼를 복원한다고 기록하지만, 이미지 증거는 없다. 오래된 `click-failure-*` 캡처는 요청대로 평가에서 제외했다.
- Playwright 시각 캡처의 `.last-run.json`은 `passed`, 실패 0건이다. 이것은 위 워크숍/일시정지 기준선의 통과를 말하며, 보이지 않는 패배 모달 이미지를 증명하지는 않는다.

## 측정 근거

최종 캔버스 인스펙터 캡처는 데스크톱과 모바일 모두 비어 있지 않았고 콘솔·페이지 오류가 0개였다. 값은 실제 결과를 그대로 옮겼다.

| 측정 | 데스크톱 | 모바일 |
| --- | ---: | ---: |
| color entropy | 2.35 bits | 2.70 bits |
| edge density | 0.105 | 0.186 |
| luminance contrast | 55.9 | 86.7 |
| dominant color share | 0.532 | 0.650 |
| draw calls | 116 | 116 |
| triangles | 30,158 | 30,158 |
| geometries | 41 | 41 |
| textures | 3 | 3 |

기본 tier 예산은 데스크톱 300 calls / 750,000 triangles / 300 geometries / 60 textures, 모바일 150 / 300,000 / 200 / 40이다. 캔버스 상태는 양쪽 모두 예산 이내다. 12개 구조물 캡처 기록 중 최대치는 11번 stage index 10의 179 calls, 70,366 triangles, 64 geometries, 3 textures로 데스크톱 시작 예산 이내다. 다만 표준 예산은 기기 성능 보증이나 FPS 측정이 아니다.

색 엔트로피(2.35/2.70)는 3.0보다 낮고 모바일 dominant-color share(0.65)는 0.6보다 높다. 이 값은 밝고 단순한 작업대 및 파스텔 구조물 표현에서 넓은 배경색이 큰 비중을 차지한다는 관찰과 일치한다. 데스크톱 contrast 55.9도 60 기준보다 낮아 lighting 점수를 3으로 올리지 않았다. edge density는 두 화면 모두 0.04 이상이며 모델 윤곽이 캔버스에서 사라지지는 않는다.

## 자동 실패와 실제 약점

- **자동 실패: 희박한 월드.** 메인 플레이 프레이밍은 거의 빈 크림색 공간 위 원형 받침과 단일 구조물이다. 정돈된 제품 연출로는 기능하지만, scorecard의 sparse-world 조건에서는 premium/showcase 주장에 장애가 된다.
- **반복 상호작용물.** 색과 표식은 다르지만 나사 몸체는 반복 실루엣이다. 이 항목은 장애물이 아니라 상호작용/수거 오브젝트로 분류해 1점을 줬다. 반복 보상 실루엣 기준을 엄격하게 적용하면 별도의 자동 실패 조건에도 해당한다.
- 특히 작은 집/정자 계열의 지붕·창 구성은 닮은 요소가 있고, 라운드 받침은 항구 환경을 보여 주기보다 제품 쇼케이스처럼 읽힌다. 모바일 일시정지 패널은 오른쪽으로 잘려 보이는 별도 레이아웃 결함이다.
- 실제 패배 UI/undo 복구 결과를 볼 캡처가 없다. QA 상태 보고는 긍정적이지만 검토자가 시각적으로 확인할 수 없다.
- 높은 key lighting은 전체 가독성을 돕지만 흰색 벽과 크림 배경의 경계를 약화한다. 모바일은 dominant share가 높고, 데스크톱 명암은 낮다.
- 수거, 상자 완성, 구조물 분해의 움직임과 효과가 정지 캡처만으로는 충분히 확인되지 않는다.

다음 시각 패스는 1) 최소한의 항구 맥락 소품/수평선/부두 그림자를 더해 받침 주변을 채우되 퍼즐 가독성을 유지하고, 2) 나사 제거·상자 완성·층 분리 피드백을 짧고 명확한 모션으로 보강하고, 3) 패배 모달과 undo 직후의 실제 브라우저 캡처를 남기는 순서가 적절하다. 반복 나사 실루엣은 퍼즐 언어의 핵심이라 여러 형태로 바꾸기보다 완료 상태·이동 경로·상자 반응을 차별화하는 편이 장르에 맞는다.

## 자동 실패 판정

- sparse-world 규칙: **예**.
- 반복 보상/상호작용 실루엣: **엄격한 해석에서는 예** (색상·표식만 다른 반복 나사).
- primitive-dominant active frame: **아니오**. 열두 구조물 캡처에는 창, 지붕, 난간, 돛대, 현창 등 서로 다른 제작 디테일이 보인다.
- 모바일 safe-area/패널 클리핑: **예**. pause-mobile 기준선에서 모달 오른쪽 경계가 viewport 밖으로 나간 것으로 보이고 닫기 버튼이 보이지 않는다.
- 활성 플레이 캡처 누락: **아니오**. stage 0–11 모두 존재한다.
- 렌더러 진단 누락: **아니오**. 최종 데스크톱·모바일 JSON과 12개 구조물 지표가 있다.
- 실제 입력/로컬 테스트 부족: 시각 캡처와 테스트 상태는 통과로 기록되어 있다. 이 리뷰 자체는 입력을 다시 재생하지 않았다.
